# 1. Introduction

## Overview

Authorization determines what authenticated users are allowed to do within InvoicePro.

Authorization is responsible for enforcing access controls across organizations, branches, business records, features, and platform resources.

Authorization answers the question:

> What can you do?

Authentication verifies identity.

Authorization verifies permissions.

Both are required before protected actions may be performed.

---

## Scope

This document covers:

- Roles
- Permissions
- Resource Access
- Tenant Access
- Branch Access
- Feature Access
- Ownership Rules
- Authorization Middleware

This document does not cover authentication mechanisms.

# 3. Authorization Principles

Authorization follows these principles.

---

## Deny By Default

Access is denied unless explicitly granted.

---

## Least Privilege

Users receive only required permissions.

---

## Organization Isolation

Users can access only authorized organizations.

---

## Resource Ownership

Users may only access resources they are authorized to use.

---

## Permission-Based Access

Permissions determine capabilities.

Roles are permission containers.

---

## Server-Side Enforcement

Authorization decisions occur on the backend.

Frontend controls are not security controls.

---

## Auditability

Authorization decisions must be traceable.

# 6. Access Control Strategy

## Overview

The Access Control Strategy defines how InvoicePro evaluates and grants access to organizations, branches, resources, features, and business operations.

The objective is to ensure that users can only access resources they are explicitly authorized to use.

Access control applies to:

- Organizations
- Branches
- Customers
- Products
- Quotations
- Invoices
- Payments
- Reports
- Settings
- Users

Every access decision must follow a consistent evaluation process.

InvoicePro follows these principles:

- Deny By Default
- Least Privilege
- Organization Isolation
- Resource Ownership
- Permission-Based Access
- Server-Side Enforcement
- Auditability

# 7. Permission Architecture

## Overview

Permissions are the smallest unit of authorization within InvoicePro.

Permissions define specific actions that a user may perform.

Roles are collections of permissions.

Users do not receive permissions directly in the standard model.

Users receive permissions through assigned roles.

# Permission Principles

InvoicePro permissions follow these principles:

- Explicit Access
- Least Privilege
- Deny By Default
- Resource-Oriented
- Action-Based
- Auditable
- Consistent Naming

# 8. Role Architecture

## Overview

Roles provide a simplified mechanism for granting permissions to users.

Instead of assigning individual permissions directly, users receive permissions through role assignments.

Roles represent business responsibilities rather than technical capabilities.

The objective is to provide:

- Simpler administration
- Consistent access control
- Faster onboarding
- Reduced permission complexity

InvoicePro ships with predefined system roles and supports future custom roles.
